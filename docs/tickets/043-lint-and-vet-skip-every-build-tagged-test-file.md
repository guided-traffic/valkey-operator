## Impact

Contributors editing the e2e, integration or image-tools tiers get no `staticcheck`, `errcheck`
(it is excluded for `_test.go` anyway, [`.golangci.yml:52-55`](../../.golangci.yml)), `unused`,
`revive` or full `vet` feedback from CI, so dead helpers and vet-class defects in roughly forty
test files accumulate unseen. The larger consequence is the two uncompiled files: the migration
e2e and the fleet-upgrade e2e can be broken by any change to shared e2e helpers, and the break
surfaces only when somebody runs them by hand — for the fleet-upgrade e2e, typically right before
a release. *(Measured 2026-09-27 at `84a39c2`: the negative control in Fact is exactly that break
passing CI's `-tags=e2e` build.)* No production code and no security property is affected.

## Options

Two decisions, taken one at a time: D1 decides where the tag list lives and so which required
job fails on a defect in the tagged tree; D2 decides how that list stays complete when a tier is
added. D2 only matters once D1 has put a list somewhere.

### D1 - where the build-tag list lives

**What the code does today.** `lint` ([`Makefile:81-85`](../../Makefile)) runs `go vet ./...`
(line 83), `$(GOFMT) -l .` (line 84) and `$(GOLANGCI_LINT) run --timeout=5m` (line 85); CI runs it
in `Code Linting` ([`release.yml:498-519`](../../.github/workflows/release.yml)), required by
ruleset 23985346 and triggered on every PR. None of the three gets a tag and `.golangci.yml:3-4`
sets none, so the 42 tagged files are outside every package those tools load, and the `gofmt`
line that does list them exits 0. Each tier's own `go test` compiles its files with vet's
11-analyzer subset (`release.yml:777`, `:415`, `:657`); `fleet_upgrade_test.go` and
`migrate_e2e_test.go` are compiled by nothing in CI.

**What the choice changes:** which configuration carries the tag list, and so which required
job fails on a compile error, a vet finding, an unused helper, a staticcheck, revive or unparam
finding or bad formatting in test code. **What it does not change:** no production code; no
test that is not run today is run - the fleet-upgrade e2e stays local-only per ADR 0017 D55, and
the Helm-migration e2e stays run by no workflow until T47 decides; the scope of `gosec` and
`govulncheck` (both skip `_test.go` by default); the `vet`, `build`, `test` and `run` targets;
branch protection (no new job). Measured inputs: all five tags compile the module together, all
tracked files pass `gofmt -s`, and the tags add 27 packages (about 3%) to the 971 golangci-lint
loads today.

- **A - `run.build-tags` in `.golangci.yml` only, `Makefile:84` deleted (recommended).** Set
  `run.build-tags: [integration, e2e, e2e_helm, fleetupgrade, imagetools]` in `.golangci.yml`;
  delete `$(GOFMT) -l .` ([`Makefile:84`](../../Makefile)); leave `vet`
  ([`Makefile:77-78`](../../Makefile)) and the `go vet ./...` line of `lint`
  ([`Makefile:83`](../../Makefile)) untagged and unchanged. With the tags, a tagged file's compile
  error (`typecheck`), vet finding (`govet`), unused helper (`unused`) and bad formatting (`gofmt`)
  each fail the run with exit 1 (measured, Fact), so one config line closes both halves inside the
  already-required job. Because the list sits in the config file and not on the Makefile command
  line, it also reaches `make lint-fix` ([`Makefile:99`](../../Makefile), `run --fix`) and every
  editor integration that reads `.golangci.yml`. `Makefile:84` goes by the ticket's own earlier
  rule ("if the formatter fails the run once the tagged files are loaded, the line is redundant

  redundant with golangci-lint's `govet` on the untagged packages exactly as it was before this
  ticket, but unlike line 84 it can fail, and removing it is a cleanup outside this defect.
  **Cost:** S, *provided* the first run of the nine non-formatting linters on the 42 files is
  small - that is the one unmeasured input (Work list item 6); compile, `gofmt -s` and import

### D2 - how the tag list stays complete

**What the code does today.** Nothing compares the build tags in the tree with any list, and
after D1 A `.golangci.yml` enumerates five tags by hand. The tree gained a tag three times since
the scaffold (`73f6efe`, `e282cc2`, `f5f3256`), none with a lint entry, and T41 once proposed a
sixth (`valkey_integration`, since superseded there). A new tier whose tag is not added reopens
this exact gap silently: its files are not linted, and if no CI job runs the tier they are
compiled by nothing. [DEVELOPER.md "Adding things"](../../DEVELOPER.md#adding-things) (line 325
ff.) has no entry for a test tier.

**What the choice changes:** only how the rule "every build tag in the tree is listed in
`run.build-tags`" is held. **What it does not change:** D1, and the close work common to both
options - the rule is written into [ADR 0017](../adr/0017-test-and-ci-policy.md) as D56 (the next
free number; the last is D55) with its index row, and DEVELOPER.md "Adding things" gets an entry
"A test tier (a build tag)": Makefile target, CI job and its required check (ADR 0017 D47), and
the `.golangci.yml` entry.

- **A - the ADR rule and the checklist entry only.** **Cost:** docs only, already part of the
  close. **Consequences:** a missed tag goes unnoticed until a review or the next audit, as the
  three missing ones did here for seven months. Choosing it departs from ADR 0017 D42 (line 700),
  "The list is guarded from both sides, because a hand-maintained one is theatre", and the choice
  would have to say why that principle does not apply to this list.
- **B - the rule, the entry and a two-sided unit drift test (recommended).** An untagged unit
  test in the style of [`internal/controller/rbac_drift_test.go`](../../internal/controller/rbac_drift_test.go):
  it walks the repository's `.go` files, parses each `//go:build` line with
  `go/build/constraint` and collects the tags that appear un-negated in the expression tree (so
  `e2e && e2e_helm` yields both tags and `!ignore_autogenerated` in
  `api/v1/zz_generated.deepcopy.go` yields none), and asserts set equality with `run.build-tags`,
  failing with the tag that is missing on either side. It parses `.golangci.yml` with
  `k8s.io/apimachinery/pkg/util/yaml`, as `rbac_drift_test.go:30` does - a direct dependency
  ([`go.mod:12`](../../go.mod)), so go.mod does not change; `sigs.k8s.io/yaml` is `// indirect`
  ([`go.mod:76`](../../go.mod)) and importing it would move it to the direct block. Placement next
  to `rbac_drift_test.go` follows the only precedent; an untagged location under `test/` (as
  `test/testimages/images_test.go`) runs in `make test-unit` as well
  ([`Makefile:112`](../../Makefile), `./...`). If T42's static-analysis net lands first, its
  untagged "test as lint" home is a third place; the mechanisms do not overlap. **Cost:** about 50 lines of test code and a revert
  check in both directions (ADR 0017 D7). **Consequences:** a new tier cannot land without the
  config line, and the converse direction makes T47 option C's deletion of
  `migrate_e2e_test.go` red until `e2e_helm` leaves the list - which the checklist would leave to
  memory. It ties a unit-tier package to two repository files, as the RBAC drift test already does.

B is marked because the tag list is a hand-maintained list whose both sides live in this
repository, and ADR 0017 D42 set the rule for exactly that shape: guard it from both sides, and
do it up front - D42's guard was built before any miss and "earned its place immediately". The
argument for A, that the heavier required-check list of D47 also stays a convention, does not
hold: ADR 0017 records that list's lack of a check as a residual risk ("Nothing enforces D47 ...
repeats the exact failure this decision was written for", line 1310 ff.), unchecked only because
branch protection is GitHub state and not a file (line 1102 ff.). A is the runner-up; it costs
nothing now and is sufficient only if nobody adds a tier, which the history above says someone
does.
