# T43 - lint and vet skip every build-tagged test file, and two of those files no CI job compiles

## Current state

**42 test files carry a build tag, and no static-analysis target passes one.**

- `test/integration/`: 15 files, `//go:build integration`. `test/e2e/`: 25 files, 23 `e2e`, one
  `e2e && e2e_helm` ([`migrate_e2e_test.go`](../../test/e2e/migrate_e2e_test.go)), one
  `e2e && fleetupgrade` ([`fleet_upgrade_test.go`](../../test/e2e/fleet_upgrade_test.go)).
  `test/imagetools/`: 2 files, `imagetools`. All 42 are in-package `_test.go` files. The only
  other tagged Go file is `api/v1/zz_generated.deepcopy.go` (`!ignore_autogenerated`, satisfied
  by default).
- `vet` ([`Makefile:77-78`](../../Makefile)) is `go vet ./...`. `lint`
  ([`Makefile:81-85`](../../Makefile)) runs `go vet ./...` (line 83), `$(GOFMT) -l .` (line 84)
  and `$(GOLANGCI_LINT) run --timeout=5m` (line 85). [`.golangci.yml`](../../.golangci.yml) sets no
  `run.build-tags` (its `run:` block, lines 3-4, holds only `allow-parallel-runners`). A file whose
  constraint is not satisfied is not loaded, so none of the 42 files is vetted with the full
  analyzer set or linted.
- Measured with `bin/golangci-lint-v2.14.0` and the repository config on a scratch module: a
  `//go:build e2e` file with an unused func, a `fmt.Printf("%d", "str")` and an unformatted func
  gives `0 issues.`, exit 0. With `run.build-tags: [e2e]` it fails with `gofmt`, `govet` and
  `unused` findings, exit 1. A tagged file calling an undefined helper fails as `typecheck` once
  its tag is set.
- The `gofmt -l .` line sees the tagged files but cannot fail: `gofmt -l` exits 0 when it lists a
  file. For untagged files it is redundant, because golangci-lint's `gofmt` formatter
  ([`.golangci.yml:61-64`](../../.golangci.yml)) already fails the run, and that formatter is
  stricter than `gofmt -l` (it simplifies, like `gofmt -s`).
- golangci-lint's `govet` runs the same analyzer set as `go vet` (plus `inline`); `.golangci.yml`
  has no `govet` settings. A tagged `go vet` line would add no analyzer.

**CI compiles the tagged files only in their own test jobs, and two files never.**

- Integration: `make test-integration-coverage` ([`release.yml:777`](../../.github/workflows/release.yml),
  `-tags=integration`, [`Makefile:129`](../../Makefile)). E2E: `make test-e2e`
  ([`release.yml:415`](../../.github/workflows/release.yml), `-tags=e2e`,
  [`Makefile:162`](../../Makefile)). Image tools: `make test-image-tools`
  ([`release.yml:657`](../../.github/workflows/release.yml), `-tags=imagetools`,
  [`Makefile:150`](../../Makefile)). A test compile runs only vet's 11-analyzer subset.
- No workflow names `e2e_helm` or `fleetupgrade`. Their targets, `test-e2e-fleet-upgrade`
  ([`Makefile:170-173`](../../Makefile)) and `test-e2e-helm` ([`Makefile:176-178`](../../Makefile)),
  are run only by hand. Measured: a call to an undefined helper in `helmRun`
  ([`fleet_upgrade_test.go:981`](../../test/e2e/fleet_upgrade_test.go)) compiles under CI's
  `-tags=e2e` and fails under `-tags=e2e,fleetupgrade`.
- The fleet-upgrade e2e is local-only by decision ([ADR 0017](../adr/0017-test-and-ci-policy.md)
  D55); the CI status of the Helm-migration e2e is T47's decision.

**Facts that bound the fix.**

- `Code Linting` ([`release.yml:498-519`](../../.github/workflows/release.yml)) runs only
  `make lint`, on every PR to `main`, and is a required check (ruleset on `main`, ADR 0017 D47).
- All five tags compile the module together: `go list -e -export -test
  -tags=integration,e2e,e2e_helm,fleetupgrade,imagetools ./...` gives 0 errors, and `test/e2e`
  has no duplicate declaration under `e2e,e2e_helm,fleetupgrade`.
- `gofmt -s -l` over all tracked Go files prints nothing, so gating formatting turns nothing red.
- The tags add 27 packages to the 971 golangci-lint loads today.
- `vet` is a prerequisite of `test`, `build`, `run`, `all`, `test-coverage` and (through `build`)
  `test-e2e-helm`; `lint` is a prerequisite of nothing. Tags on `vet` would couple the operator
  build to test-code findings.
- `gosec` and `govulncheck` are not part of this gap: both skip `_test.go` files by default, and
  [`Makefile:296`](../../Makefile) and [`Makefile:301`](../../Makefile) pass neither `-tests` nor
  `-test`.
- A `go test -run '^$'` compile step is not compile-only: it runs the `TestMain` of
  [`test/integration/suite_test.go:60-70`](../../test/integration/suite_test.go), which starts
  envtest and panics without `KUBEBUILDER_ASSETS`.
- Nothing compares the build tags in the tree with any list, and
  [DEVELOPER.md "Adding things"](../../DEVELOPER.md#adding-things) has no entry for a test tier.

**Impact.** Contributors editing the e2e, integration or image-tools tiers get no `staticcheck`,
`unused`, `revive`, `unparam` or full `vet` feedback from CI, so dead helpers and vet-class
defects in about forty test files accumulate unseen. Worse, any change to shared e2e helpers can
break the migration e2e and the fleet-upgrade e2e with CI green; the break surfaces only when
someone runs them by hand, for the fleet-upgrade e2e typically right before a release. No
production code and no security property is affected.

**Adjacent finding in the same file.** [`.golangci.yml:70`](../../.golangci.yml) lists `goconst`
as a `goimports` local prefix. No import path starts with it, so it has no effect.

## Open questions

### Q1: Where does the build-tag list live?

It decides which required job fails on a compile error, vet finding, unused helper, lint finding
or bad formatting in tagged test code. It does not change which tests run, the scope of `gosec`
or `govulncheck`, or the `vet`, `build`, `test` and `run` targets.

- **A - `run.build-tags` in `.golangci.yml` only, `Makefile:84` deleted (recommended).** One config
  line closes both halves in the already-required job: typecheck, `govet`, `unused`, `staticcheck`
  and the formatter all see the tagged files, and the list also reaches `make lint-fix` and
  editors. Line 84 can then only print what the run already fails on. Cost S if the first run
  (item 1) is small.
- **B2 - the tags on the `go vet` line of `lint` only.** Closes the uncompiled-file half with the
  full vet, nothing else; `staticcheck`, `unused`, `revive`, `unparam` and the formatter still do
  not see the tagged files. Cost XS to S.

A closes both halves for the same one-line cost and catches exactly the dead e2e helpers the
impact names. B2 is the fallback only if item 1 measures a first run larger than S: then B2 lands
first to close the uncompiled-file half, and A follows after the cleanup.

**Answer:** _open_

### Q2: How does the tag list stay complete when a tier is added?

After Q1 A, `.golangci.yml` enumerates five tags by hand, and a new tag that is not added reopens
this gap silently. Both options include the ADR 0017 D56 rule and the DEVELOPER.md checklist
entry (item 6).

- **A - the rule and the checklist entry only.** Docs only. A missed tag goes unnoticed until a
  review; it departs from ADR 0017 D42 ("a hand-maintained one is theatre") and would have to say
  why.
- **B - the rule, the entry and a two-sided unit drift test (recommended).** An untagged unit test
  next to [`internal/controller/rbac_drift_test.go`](../../internal/controller/rbac_drift_test.go)
  walks the `.go` files, parses each `//go:build` line with `go/build/constraint`, collects the
  un-negated tags (so `e2e && e2e_helm` yields both, `!ignore_autogenerated` none), and asserts
  set equality with `run.build-tags`. It parses YAML with `k8s.io/apimachinery/pkg/util/yaml` as
  `rbac_drift_test.go:30` does, so go.mod does not change. About 50 lines plus revert checks.

B, because the tag list is a hand-maintained list with both sides in this repository, the exact
shape ADR 0017 D42 says is guarded from both sides. It also turns red if T47 deletes
`migrate_e2e_test.go` without removing `e2e_helm` from the list.

**Answer:** _open_
