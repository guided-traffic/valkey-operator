# Package map

Where things live, and what each package is responsible for. One line per file where the
file's name does not already say it. The picture these packages add up to is
[architecture.md](architecture.md); the order they run in during a reconcile pass is
[reconcile-loop.md](reconcile-loop.md).

Surveyed 2026-09-27 against the tree; a file added since is missing here until someone adds
its line.

## Entry points — `cmd/`

One binary, `manager`. [`cmd/main.go`](../../cmd/main.go) looks at the first argument and runs
one of four modes.

| Path | Responsibility |
|---|---|
| [`main.go`](../../cmd/main.go) | Operator mode: the operator flags (`bindOperatorFlags`), the controller-runtime manager, the `ValkeyReconciler`, the metrics collector, the health and ready checks. Dispatches `sidecar`, `migrate` and `observer` before any of that |
| [`sidecar/`](../../cmd/sidecar/) | `manager sidecar`: parses the sidecar flags and calls `internal/sidecar.Run` |
| [`observer/`](../../cmd/observer/) | `manager observer`: parses the observer flags and calls `internal/observer.Run` |
| [`migrate/`](../../cmd/migrate/) | `manager migrate`, run by the chart's pre-upgrade hook Job: lists every `Valkey` cluster-wide and patches missing field defaults (`applyDefaults`) into each; one failing patch does not stop the others, and any failure fails the Job |

## The reconciler — `internal/controller/`

| Path | Responsibility |
|---|---|
| [`valkey_controller.go`](../../internal/controller/valkey_controller.go) | `ValkeyReconciler` and `InstanceChecker`, the RBAC markers, `Reconcile`, the resource step list and every per-object reconcile function, the status computation and write, the no-master recovery, `SetupWithManager` and the Secret watch |
| [`rolling_update.go`](../../internal/controller/rolling_update.go) | Both rolling updates: the data tier (standalone, multi-replica without Sentinel with its manual failover and topology restoration, Sentinel-driven failover — the first trigger `COORDINATED`, forced where a Sentinel refuses the option and on the retrigger) and the Sentinel tier; outdated-pod detection, the bounded waits, the rolling-update state annotations, the rolling-update split-brain resolver |
| [`master_handover.go`](../../internal/controller/master_handover.go) | The gate in front of the delete of an outdated pod on the Sentinel data-tier roll (`gateOutgoingPodDelete`, from `replaceRemainingPods`): `verifyNewMasterReady` — every other current pod answers as a synced replica, the new master has at least that many replicas attached and never none, its key count is readable — then the dataset veto and the role check on the pod about to be deleted; the bounded hold and its `MasterHandoverStalled` report; and `replicaOfRefusal`, the dataset veto `forceReplicaConnections` asks before it sends any `REPLICAOF` |
| [`steady_state_master.go`](../../internal/controller/steady_state_master.go) | The split-brain check outside a rolling update, with its adoption and demotion evidence |
| [`split_brain_report.go`](../../internal/controller/split_brain_report.go) | The `MultipleMasters` condition and the delayed `SplitBrainDetected` Warning |
| [`reconcile_blocked.go`](../../internal/controller/reconcile_blocked.go) | The `ReconcileBlocked` condition: admission-rejection classification, message compaction, the blocked-pass marker on the context |
| [`foreign_object.go`](../../internal/controller/foreign_object.go) | Ownership proofs before a write or delete: the `…NotOwned` Event reasons, `deleteIfOwned`, `podIsOurs`, `deleteOwnedPod`, and the per-pass recheck (`passState`, `requestRecheck`) |
| [`condition_registry.go`](../../internal/controller/condition_registry.go) | One row per condition type — level, edge or history — read only by the tests that enforce it |
| [`nudge.go`](../../internal/controller/nudge.go) | The StatefulSet nudge for a StatefulSet short of pods, and the in-memory tracker it shares with the wait bounds |
| [`ratelimiter.go`](../../internal/controller/ratelimiter.go) | The work-queue rate limiter (30 s backoff cap) and `DefaultMaxConcurrentReconciles` (4) |
| [`pdb.go`](../../internal/controller/pdb.go) | The data and Sentinel PodDisruptionBudgets and their configuration warnings |
| [`volumeclaim_conflict.go`](../../internal/controller/volumeclaim_conflict.go) | The refusal of a StatefulSet whose `volumeClaimTemplates` no longer match the spec, and the `StorageSpecNotApplied` condition |
| [`tls_material.go`](../../internal/controller/tls_material.go) | The TLS material record on the pod templates (`ensureTLSMaterialRecord`) and the `TLSMaterialStale` report |
| [`pod_hardening.go`](../../internal/controller/pod_hardening.go) | The `Localhost` seccomp allow-list gate and `writeWorkload`, which reads back whether the API server dropped `hostUsers` |
| [`pod_security_migration.go`](../../internal/controller/pod_security_migration.go) | Whether the data template carries the ownership repair, and which single root pod is deferred (`PodSecurityUpdatePending`) |
| [`rw_service_report.go`](../../internal/controller/rw_service_report.go) | Whether the `-rw` Service can select a master at all (`RWServiceEmpty`) |

hashes, and the drift comparisons. They make no API calls.

| Path | Responsibility |
|---|---|
| [`statefulset.go`](../../internal/builder/statefulset.go) | The data StatefulSet: pod spec, Valkey container, sidecar container, exporter container, init container and its election script, drain preStop hook, token projection, volume claims; `ComputePodSpecHash`; `StatefulSetHasChanged` and the field-by-field pod-spec comparison |
| [`sentinel.go`](../../internal/builder/sentinel.go) | `sentinel.conf`, the Sentinel ConfigMap and StatefulSet, the Sentinel init script, `SentinelQuorumFor`, `ComputeSentinelPodSpecHash`, and the `vko.gtrfc.com/known-master` annotation key |
| [`configmap.go`](../../internal/builder/configmap.go) | `valkey.conf` for the master and replica ConfigMaps, and the config hash |
| [`service.go`](../../internal/builder/service.go) | The headless, `-rw`, `-r`, `-all`, Sentinel headless and metrics Services |
| [`certificate.go`](../../internal/builder/certificate.go) | cert-manager Certificates, as `unstructured` |
| [`servicemonitor.go`](../../internal/builder/servicemonitor.go) | The Prometheus-Operator ServiceMonitor, as `unstructured` |
| [`networkpolicy.go`](../../internal/builder/networkpolicy.go) | The Valkey, Sentinel and observer NetworkPolicies |
| [`pdb.go`](../../internal/builder/pdb.go) | The two PodDisruptionBudgets |
| [`affinity.go`](../../internal/builder/affinity.go) | The pod anti-affinity term |
| [`rbac.go`](../../internal/builder/rbac.go) | The per-cluster sidecar ServiceAccount, Role and RoleBinding |
| [`observer.go`](../../internal/builder/observer.go) | The observer Deployment and ServiceAccount, and the Deployment's drift comparison |
| [`pod_security.go`](../../internal/builder/pod_security.go) | The rootless posture applied by one walk over every container, the `check-data-writable` pre-flight, the `fix-data-ownership` repair, and the securityContext comparisons |
| [`tls_material.go`](../../internal/builder/tls_material.go) | The TLS material fingerprint, its stamping onto a pod template, and reading it back |
| [`annotations.go`](../../internal/builder/annotations.go) | The operator-version, config-hash, pod-spec-hash, nudge and TLS-material annotation keys and their helpers |

| [`image_requirements.go`](../../internal/builder/image_requirements.go) | `RequiredImageTools`, every executable the generated scripts expect in the Valkey image |

## Shared and runtime packages

| Path | Responsibility |
|---|---|
| [`internal/common/`](../../internal/common/) | Labels, selector labels, StatefulSet and headless Service names, `ExtractVersionFromImage`; plus the drain-signal constants and the `vko.gtrfc.com/drain-promoted-at` key, kept here because `internal/sidecar` and the operator side both import this package |
| [`internal/health/`](../../internal/health/) | `Checker`, the reconciler's default `InstanceChecker`: `CheckCluster` assesses master, replicas and Sentinel, and counts a replica as synced only from that pod's own `INFO replication` — the reply the concurrent master probe already collected, never the master's `connected_slaves`; `PingPod`, `GetReplicationInfo`, `PodAddressForComponent`. `served_certificate.go` compares, report-only, the certificate a pod serves against the one its Secret holds |
| [`internal/valkeyclient/`](../../internal/valkeyclient/) | A minimal RESP client with no external Redis library: one dial per command, 5 s default timeout, plain or TLS, with the replication, Sentinel, `REPLICAOF`, `WAIT` and `DBSIZE` commands the other packages need. `ReplicationInfo.NotEstablishedReason` is the one "synced" predicate the reconciler, the health checker, the observer and the sidecar share; an error reply comes back as `ReplyError`, whose `Code` a caller can act on |
| [`internal/sidecar/`](../../internal/sidecar/) | The process in every data pod: `run.go` (loop and shutdown), `labeler.go` (patches the pod's `instanceRole` label, with a Sentinel cross-check), `drain.go` (the SIGTERM failover and the drain-complete marker), `health.go` (`/readyz`, `/healthz`) |
| [`internal/observer/`](../../internal/observer/) | The optional observer Deployment: `observer.go` (polling loop and result), `checks.go` (master discovery, replication asked of every data pod, write/read, Sentinel checks), `metrics.go`, `server.go` (`/readyz`, `/healthz`, `/metrics`) |
| [`internal/metrics/`](../../internal/metrics/) | `ValkeyCollector`: the `vko_valkey_*` series on the operator's `/metrics`, read from the manager cache at scrape time |
| [`internal/tlsmaterial/`](../../internal/tlsmaterial/) | `Reloader`: a `*tls.Config` rebuilt per dial from the mounted material, for the sidecar and the observer |

## Where the tests are

Unit tests sit next to the code as `*_test.go` and carry no build tag. The other tiers have
their own directories and tags; what each is for is [testing.md](testing.md).

| Path | Tag | Holds |
|---|---|---|
| [`test/integration/`](../../test/integration/) | `integration` | envtest suites sharing one API server and one manager (`suite_test.go`) |
| [`test/e2e/`](../../test/e2e/) | `e2e` (`e2e && fleetupgrade`, `e2e && e2e_helm` for one file each) | Kind suites; shared helpers in `e2e_test.go`, the Helm values the E2E install uses in `helm-values.yaml`, the self-signed issuer in `testdata/` |
| [`test/imagetools/`](../../test/imagetools/) | `imagetools` | Checks against the pinned Valkey images, with docker and no cluster |
| [`test/testimages/`](../../test/testimages/) | none | The Valkey image pins; not a test package itself |
